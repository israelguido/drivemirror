# DriveMirror Internationalization Design

## Intent

DriveMirror must be usable in Brazilian Portuguese, English, and Spanish. It chooses the language from the desktop locale by default and lets the user override that choice in the settings window.

## Behavior

- Add a language setting with `system`, `pt-BR`, `en`, and `es` values; existing TOML files default to `system`.
- Under `system`, locales beginning with `pt` use Brazilian Portuguese, locales beginning with `es` use Spanish, and every other locale uses English.
- A language selector in the main window persists the override with the rest of the settings and updates visible window text immediately.
- Window labels, buttons, status/error messages, tray menu items, desktop name/comment, and user-facing validation messages are translated.
- User paths, remote names, rclone output, patterns, brand names, and configuration keys are not translated.

## Approach

Use a small compile-time Rust message catalog and a typed `Language` enum. This was selected over gettext or external catalogs because the MVP has three languages, needs no translator tooling, and should add no dependency or runtime file. Automatic-only detection was rejected because the user explicitly requested a manual override.

## Constraints

Missing or invalid language values fall back to `system`. The app remains one process and the configuration format stays backward compatible. No additional synchronization behavior is introduced.
